# article-service

Phase 3 of the microservice extraction (`docs/microservice-extraction/phases/phase-3-tag.md`):
the Tag slice of the Article domain of the Conduit monolith as a standalone Spring Boot 2.6.3 /
Java 11 service. Phase 3 stands the service up with the tag tables (`tags`, `article_tags`) and the
internal tag API; Phase 4 moves `articles` into it (the `articles` table is already created by
`V1__` but stays empty). It never reads the monolith's `dev.db`. Authorization stays in the
monolith: `PUT` only requires *a* valid monolith-issued token.

This directory is an **independent Gradle build** (own `settings.gradle` and wrapper). The root
build does not include it and must never `include 'article-service'`; the root Spotless block
excludes `article-service/**`.

## Build, test, run

Spotless (google-java-format) needs **JDK 11**; export `JAVA_HOME` first.

```bash
export JAVA_HOME=/path/to/jdk11
cd article-service

./gradlew build              # compile + unit/@WebMvcTest/@MybatisTest + contract verification + spotless + jacoco
./gradlew test               # unit tests only
./gradlew contractTest       # provider-side Spring Cloud Contract verification (MOCKMVC mode)
./gradlew spotlessApply      # format before committing
./gradlew bootRun            # :8083, deletes and recreates ./article.db (Flyway V1 + V2 seed)
# or, after build:
java -jar build/libs/article-service-0.0.1-SNAPSHOT.jar
```

| Item | Value |
|---|---|
| Port | `8083` (`server.port`, override with `SERVER_PORT`) |
| Database | `jdbc:sqlite:article.db` in the working directory (git-ignored) |
| Migrations | `src/main/resources/db/migration/V1__create_article_tables.sql` (`articles`, `tags`, `article_tags`; DDL identical to the monolith: no FKs, no unique constraint on `tags.name`), `V2__seed_tags.sql` (the monolith's `tags` + `article_tags` seed rows, same order; `articles` empty) |
| Test profile | `application-test.properties`: `jdbc:sqlite::memory:`, `spring.flyway.target=1` (no seed) |
| Health | `GET /actuator/health` -> `{"status":"UP"}` |

### Properties (`src/main/resources/application.properties`)

| Property | Default | Notes |
|---|---|---|
| `server.port` | `8083` | |

not root-wrapped.

## Internal REST API (canonical contract, phase-3-tag.md §2.1)

All responses are JSON. Errors use the monolith envelope `{"errors":{"body":["..."]}}`:
`401` missing or invalid token, `422` invalid body (missing `tags`, blank tag `name`, bad JSON).

Ordering is the monolith's: `GET /internal/tags` is literally `select name from tags` (rowid
order, no `DISTINCT`, duplicates included if present); `tagList` and `articleIds` follow
`article_tags` rowid order (the monolith's join order).

| Method / path | Request | Response | Auth |
|---|---|---|---|
| `GET /internal/tags` | — | `200 {"tags":["java",...]}` | none |
| `GET /internal/articles/tags?articleIds=a,b,c` | — | `200 {"articleTags":[{"articleId":"a","tagList":[...]},...]}` — one entry per requested id in request order (empty `tagList` for ids with no tags); empty/missing `articleIds` -> `{"articleTags":[]}` | none |
| `GET /internal/tags/{name}/article-ids` | — | `200 {"articleIds":[...]}` distinct; unknown tag -> `{"articleIds":[]}` | none |
| `PUT /internal/articles/{articleId}/tags` | `{"tags":[{"id":"<uuid>","name":"..."}]}` — ids are generated by the caller so dual-write produces identical `tags` rows | `200 {"articleId":"...","tagList":[...]}` (the article's full tag list after the call). Idempotent: for each tag reuse the existing row by `name`, else insert with the supplied id; insert `(article_id, tag_id)` only if the pair is absent; never deletes relations (mirrors `MyBatisArticleRepository.createNew`) | `Authorization: Token <jwt>` (any valid user) |
| `GET /actuator/health` | — | `200 {"status":"UP"}` | none |

Example (token from `POST http://localhost:8080/users/login` on the monolith):

```bash
curl -s http://localhost:8083/internal/tags
# {"tags":["java","spring-boot","web-development","tutorial","best-practices","microservices","api-design"]}

curl -s 'http://localhost:8083/internal/articles/tags?articleIds=article-1,article-3,nope'
# {"articleTags":[{"articleId":"article-1","tagList":["java","spring-boot","tutorial"]},{"articleId":"article-3","tagList":["spring-boot","microservices","best-practices"]},{"articleId":"nope","tagList":[]}]}

curl -s http://localhost:8083/internal/tags/java/article-ids
# {"articleIds":["article-1","article-4","article-5"]}

curl -s -X PUT -H 'Content-Type: application/json' -H "Authorization: Token $JWT" \
  -d '{"tags":[{"id":"ignored-existing","name":"java"},{"id":"9f1c2a1e-0000-4000-8000-000000000001","name":"kotlin"}]}' \
  http://localhost:8083/internal/articles/article-1/tags
# {"articleId":"article-1","tagList":["java","spring-boot","tutorial","kotlin"]}
```

## Layout

```
src/main/java/io/spring/article/
  ArticleServiceApplication.java
  api/            TagInternalApi, PutArticleTagsRequest, TagRequest, exception/ (error envelope), security/ (JwtTokenFilter, WebSecurityConfig)
  core/           tag/ Tag, TagRepository; service/ JwtService
  application/    TagQueryService, TagCommandService, data/ ArticleTagsData, ArticleTagRow
  infrastructure/ MyBatis TagMapper + TagReadService, MyBatisTagRepository, DefaultJwtService
src/main/resources/mapper/*.xml           MyBatis XML mappers
src/test/java/io/spring/article/          @MybatisTest, @WebMvcTest, @SpringBootTest, contract base class
src/test/resources/contracts/tag/         Spring Cloud Contract DSL for every internal endpoint (+ 401/422 and empty cases)
```

The contracts are verified against `TagInternalApi` with standalone MockMvc
(`TagInternalApiContractBase`); the same files produce the WireMock stubs the monolith's
consumer tests can run against (`./gradlew publishToMavenLocal` publishes
`article-service-0.0.1-SNAPSHOT-stubs.jar`).
