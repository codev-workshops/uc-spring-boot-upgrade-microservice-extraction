# article-service

Phases 3 and 4 of the microservice extraction (`docs/microservice-extraction/phases/phase-3-tag.md`,
`phase-4-article.md`): the Article domain (articles + tags) of the Conduit monolith as a standalone
Spring Boot 2.6.3 / Java 11 service. Phase 3 stood the service up with the tag tables (`tags`,
`article_tags`) and the internal tag API; Phase 4 adds the `articles` rows and the internal article
API. It never reads the monolith's `dev.db`. Authorization stays in the monolith (author checks,
username -> id resolution, profile/favorite composition): mutations only require *a* valid
monolith-issued token, except `POST /internal/articles` which requires token subject == `userId`.

This directory is an **independent Gradle build** (own `settings.gradle` and wrapper). The root
build does not include it and must never `include 'article-service'`; the root Spotless block
excludes `article-service/**`.

## Build, test, run

Spotless (google-java-format) needs **JDK 11**; export `JAVA_HOME` first.

```bash
export JAVA_HOME=/path/to/jdk11
cd article-service

./gradlew build              # compile + unit/@WebMvcTest/@MybatisTest + contract verification + spotless + jacoco
./gradlew test               # unit tests only
./gradlew contractTest       # provider-side Spring Cloud Contract verification (MOCKMVC mode)
./gradlew spotlessApply      # format before committing
./gradlew bootRun            # :8083, deletes and recreates ./article.db (Flyway V1 + V2/V3 seed)
# or, after build:
java -jar build/libs/article-service-0.0.1-SNAPSHOT.jar
```

| Item | Value |
|---|---|
| Port | `8083` (`server.port`, override with `SERVER_PORT`) |
| Database | `jdbc:sqlite:article.db` in the working directory (git-ignored) |
| Migrations | `src/main/resources/db/migration/V1__create_article_tables.sql` (`articles`, `tags`, `article_tags`; DDL identical to the monolith: no FKs, no unique constraint on `tags.name`), `V2__seed_tags.sql` (the monolith's `tags` + `article_tags` seed rows, same order), `V3__seed_articles.sql` (the monolith's `articles` seed rows) |
| Test profile | `application-test.properties`: `jdbc:sqlite::memory:`, `spring.flyway.target=1` (no seed) |
| Health | `GET /actuator/health` -> `{"status":"UP"}` |

## Internal REST API (canonical contract, phase-3-tag.md §2.1)

All responses are JSON. Errors use the monolith envelope `{"errors":{"body":["..."]}}`:
`401` missing or invalid token, `422` invalid body (missing `tags`, blank tag `name`, bad JSON).

Ordering is the monolith's: `GET /internal/tags` is literally `select name from tags` (rowid
order, no `DISTINCT`, duplicates included if present); `tagList` and `articleIds` follow
`article_tags` rowid order (the monolith's join order).

| Method / path | Request | Response | Auth |
|---|---|---|---|
| `GET /internal/tags` | — | `200 {"tags":["java",...]}` | none |
| `GET /internal/articles/tags?articleIds=a,b,c` | — | `200 {"articleTags":[{"articleId":"a","tagList":[...]},...]}` — one entry per requested id in request order (empty `tagList` for ids with no tags); empty/missing `articleIds` -> `{"articleTags":[]}` | none |
| `GET /internal/tags/{name}/article-ids` | — | `200 {"articleIds":[...]}` distinct; unknown tag -> `{"articleIds":[]}` | none |
| `PUT /internal/articles/{articleId}/tags` | `{"tags":[{"id":"<uuid>","name":"..."}]}` — ids are generated by the caller so dual-write produces identical `tags` rows | `200 {"articleId":"...","tagList":[...]}` (the article's full tag list after the call). Idempotent: for each tag reuse the existing row by `name`, else insert with the supplied id; insert `(article_id, tag_id)` only if the pair is absent; never deletes relations (mirrors `MyBatisArticleRepository.createNew`) | `Authorization: Token <jwt>` (any valid user) |
| `GET /actuator/health` | — | `200 {"status":"UP"}` | none |

## Internal REST API — articles (canonical contract, phase-4-article.md §2.1)

An article `row` is `{id, slug, title, description, body, userId, createdAt, updatedAt, tagList}` —
no `author`, `favorited` or `favoritesCount` (the monolith composes those). Timestamps are
ISO-8601 UTC with millis (`2024-01-31T10:15:30.123Z`), exactly like the monolith's JSON.
`authorId` is a resolved user id and `ids` an article-id allow-list: the monolith resolves
`author=`/`favorited=` usernames before calling. Errors: `404 {"errors":{"body":["article not found"]}}`,
`401 {"errors":{"body":["missing or invalid token"]}}`, `403`, and the monolith's
`422 {"errors":{"title":["article name exists"]}}` on a slug clash.

| Method / path | Request | Response | Auth |
|---|---|---|---|
| `GET /internal/articles/{id}` | — | `200 {"article":row}` / `404` | none |
| `GET /internal/articles/by-slug/{slug}` | — | `200 {"article":row}` / `404` | none |
| `GET /internal/articles?ids=a,b,c` | — | `200 {"articles":[row...]}` ordered `created_at DESC`; empty `ids` -> `[]` | none |
| `GET /internal/articles/ids?tag=&authorId=&ids=&offset=&limit=` | — | `200 {"articleIds":[...],"count":N}` — `DISTINCT` ids `ORDER BY created_at DESC LIMIT offset,limit`, `count` = total matching; an empty `ids=` allow-list short-circuits to `[]`/`0` | none |
| `GET /internal/articles/ids/cursor?tag=&authorId=&ids=&limit=&direction=next\|prev[&cursor=<millis>]` | — | `200 {"articleIds":[...]}` — up to `limit+1` ids, `created_at <` cursor `DESC` for `next`, `>` `ASC` for `prev` | none |
| `GET /internal/articles/feed?authorIds=&offset=&limit=` | — | `200 {"articles":[row...],"count":N}`; empty `authorIds` -> `[]`/`0` | none |
| `GET /internal/articles/feed/cursor?authorIds=&limit=&direction=[&cursor=]` | — | `200 {"articles":[row...]}` (up to `limit+1`) | none |
| `POST /internal/articles` | `{id, slug, title, description, body, userId, createdAt, updatedAt, tags:[{id,name}]}` — id/slug/timestamps/tag ids supplied by the caller and stored verbatim; absent ones fall back to the monolith's rules (UUID, `toSlug(title)`, now) | `201 {"article":row}`; `200` with the existing row when the id already exists; `422` title envelope when the slug belongs to another id; `403` when token subject != `userId`. Article + tags (reuse by name / insert with supplied id / pair only if absent) in one transaction | `Authorization: Token <jwt>`, subject == `userId` |
| `PUT /internal/articles/{id}` | `{title?, description?, body?}` | `200 {"article":row}` / `404`; blank fields skipped, slug regenerated from a non-blank title, `updated_at` NOT written (monolith quirk); `422` title envelope on slug clash | `Authorization: Token <jwt>` |
| `DELETE /internal/articles/{id}` | — | `204`, idempotent; deletes only the `articles` row (`article_tags` untouched) | `Authorization: Token <jwt>` |

```bash
curl -s 'http://localhost:8083/internal/articles/ids?tag=java&limit=2'
# {"articleIds":["article-5","article-4"],"count":3}
curl -s http://localhost:8083/internal/articles/by-slug/getting-started-with-spring-boot
curl -s 'http://localhost:8083/internal/articles/feed?authorIds=user-1'
curl -s -X POST -H "Authorization: Token $TOKEN" -H 'Content-Type: application/json' \
  -d '{"id":"9f1c2a1e-0000-4000-8000-0000000000aa","title":"Hello","description":"d","body":"b","userId":"<token subject>","tags":[{"id":"9f1c2a1e-0000-4000-8000-0000000000ab","name":"java"}]}' \
  http://localhost:8083/internal/articles
```

Example (token from `POST http://localhost:8080/users/login` on the monolith):

```bash
curl -s http://localhost:8083/internal/tags
# {"tags":["java","spring-boot","web-development","tutorial","best-practices","microservices","api-design"]}

curl -s 'http://localhost:8083/internal/articles/tags?articleIds=article-1,article-3,nope'
# {"articleTags":[{"articleId":"article-1","tagList":["java","spring-boot","tutorial"]},{"articleId":"article-3","tagList":["spring-boot","microservices","best-practices"]},{"articleId":"nope","tagList":[]}]}

curl -s http://localhost:8083/internal/tags/java/article-ids
# {"articleIds":["article-1","article-4","article-5"]}

curl -s -X PUT -H 'Content-Type: application/json' -H "Authorization: Token $JWT" \
  -d '{"tags":[{"id":"ignored-existing","name":"java"},{"id":"9f1c2a1e-0000-4000-8000-000000000001","name":"kotlin"}]}' \
  http://localhost:8083/internal/articles/article-1/tags
# {"articleId":"article-1","tagList":["java","spring-boot","tutorial","kotlin"]}
```

## Layout

```
src/main/java/io/spring/article/
  ArticleServiceApplication.java
  JacksonCustomizations.java  Joda DateTime <-> ISO-8601 UTC (same as the monolith)
  api/            TagInternalApi, ArticleInternalApi, request DTOs, exception/ (error envelopes), security/ (JwtTokenFilter, WebSecurityConfig)
  core/           tag/ Tag, TagRepository; article/ Article, ArticleRepository; service/ JwtService
  application/    Tag{Query,Command}Service, Article{Query,Command}Service, Page, CursorPageParameter, data/
  infrastructure/ MyBatis TagMapper/ArticleMapper + TagReadService/ArticleReadService, MyBatis*Repository, DateTimeHandler, DefaultJwtService
src/main/resources/mapper/*.xml           MyBatis XML mappers
src/test/java/io/spring/article/          @MybatisTest, @WebMvcTest, @SpringBootTest, contract base class
src/test/resources/contracts/{tag,article}/  Spring Cloud Contract DSL for every internal endpoint (+ 401/403/404/422 and empty cases)
```

The contracts are verified against `TagInternalApi` / `ArticleInternalApi` with standalone MockMvc
(`TagInternalApiContractBase` / `ArticleInternalApiContractBase`, mapped per contract package in
`build.gradle`); the same files produce the WireMock stubs the monolith's
consumer tests can run against (`./gradlew publishToMavenLocal` publishes
`article-service-0.0.1-SNAPSHOT-stubs.jar`).
